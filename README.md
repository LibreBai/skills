# skills

安全产品软件工程规范与 AI 辅助开发流程仓库。

本仓库沉淀以下内容，供各模块开发时由 AI（如 Claude Code skill）加载执行：

- **standards/** — 通用规范：命名、字段约束、日志输出、界面文案，均为硬约束，任何调用方指令不得降低其要求
- **product/** — 产品资料模板：产品形态、Web 风格，新产品实例化时填写
- **playbook/** — 开发流程：各阶段产物定义与对应 skill 规划
- **templates/** — 各阶段文档模板（待建）
- **bespoke-skills/** — 自研 skills：契合个人开发流程的调用方 skill（收录标准见 bespoke-skills/README.md）
- **awesome-skills/** — 搜集的优秀 skills：外来参考与直接复用件（如 grill-me）

## standards/ — 通用规范

规范文件统一为 callee 格式：**适用范围 + 优先级声明 + 参数表 + 规则编号 + 正反示例 + 完成前自检清单**。规范间互相引用（如术语表是命名的唯一登记处，日志脱敏与字段校验联动），引用关系以规范文件内声明为准。

| 文件 | 内容 | 规则编号 |
|------|------|---------|
| naming-standard.md | 命名格式表与命名规则：术语表先行、同一概念全工程同名、生产方与消费方字段名完全一致 | NAME-01 ~ NAME-09 |
| naming-glossary.md | 字段与概念标准名、枚举取值统一；标准名一经登记即全工程统一使用，禁用同义词仅供检索比对 | — |
| field-constraint.md | 输入校验：校验顺序固定、UTF-8 字节长度、禁止一切空白、注入风险字符、密码加盐慢哈希 | FIELD-01 ~ FIELD-09 |
| logging-standard.md | 日志等级语义、管理操作日志五要素、全局脱敏、高频日志限频与采样、用户错误与系统内部错误的分级处置 | LOG-01 ~ LOG-11 |
| ui-standard.md | Web 页面文案与对齐：书面语、句读仅用全角逗号、标签与控件间禁冒号、横平竖直对齐、占位符不得代替标签；常见浏览器兼容与窗口/缩放自适应 | UI-01 ~ UI-17 |

## product/ — 产品资料模板

新产品实例化时按模板填写，「【待填】」为必须填充的槽位：

- **产品形态文档**：记录产品内既定事实——环境变量、网口分配、端口、系统路径等。各模块只能使用明确分配给自己的资源；固定值与已占用项不得改动、不得复用；新增占用必须先登记再使用。
- **产品 Web 风格文档**：设计系统、布局模板、交互惯例，以及与规范的界面联动点（如敏感字段掩码固定 `******`，与日志脱敏口径一致）。

product/ 下的文档只做绑定与补充，不得降低 standards 下任何规范的要求；与规范冲突时以规范为准。

## playbook/ — 开发流程

模块开发按阶段推进，产物落在模块目录的 `docs/`、`prototype/`、`test/` 下：

| 阶段 | 产物 | 要点 |
|------|------|------|
| 1-1 调研 | 需求文档 | 原始需求不可修改；每项诉求逐项闭环：已落实 / 已调整 / 暂不实现 / 待确认 |
| 1-2 调研 | 技术调研 | 结合产品形态调研可行技术，环境搭建实测，完整保留测试流程与结果 |
| 2-1 开发 | 概要设计 | Mermaid 图为主，面向人 |
| 2-2 开发 | 详细设计 + demo 原型 | 函数/结构体级，面向 AI；原型需遵循产品 Web 风格文档 |
| 2-3 开发 | 程序实现及代码审查 | 实现须满足各通用规范 |
| 3-1 测试 | 测试及交付文档 | 测试环境、CLI、功能与系统配置项、Web 增删改查与风格一致性，与需求闭环 |
| 交付 | 使用场景 + 用户手册 | 面向使用者 |

## 使用方式

规范与模板由调用方 skill 在对应开发阶段加载执行（skill 待建，规划见 [playbook/流程思考过程.md](playbook/流程思考过程.md)）。bespoke-skills/ 下的自研 skill 不绑定开发阶段，按需由用户直接调用。
