适用：新增/修改日志调用、管理类接口（增删改查/登录登出/导入/导出/下发）、业务事件记录、错误提示时生效。
优先级：本规范为硬约束，调用方指令不得降低其要求。本规范只约定什么情况下输出、用什么等级、输出什么内容，不绑定具体日志接口，日志设施由所在工程提供。

## 等级与使用场景对照表

| 等级 | 语义 | 使用场景 |
|------|------|---------|
| ALERT | 遭受攻击 | 业务日志中的攻击、防护告警 |
| ERROR | 操作/运行失败：用户操作错误（提示错因与改法）或系统内部错误（对外仅提示联系支持，日志定位） | 用户操作错误；系统内部错误 |
| WARNING | 暂不影响功能但需用户关注 | 证书/License 即将过期、资源超阈值、配置项废弃提示 |
| INFO | 用户操作告知、系统正常运行信息 | 管理操作日志的成功记录；业务日志的常规运行事件 |
| DEBUG | 内部调试，不展示给客户 | 详细出错位置、难以复现问题的上下文 |

## 参数表

| 项 | 值 |
|----|----|
| 操作类型枚举 | 新增/修改/删除/查询/登录/登出/导入/导出/下发（中文仅用于日志文案与界面显示；结构化字段的英文标准值见术语表（naming-glossary.md）operation_type；业务日志字段与审计要素标准名同见该术语表） |
| 敏感字段清单 | 密码、密钥/共享密钥（PSK）、认证凭据、证书私钥、SNMP 团体字、令牌/会话标识（token/session id）、内嵌凭据的 URL/连接串 |
| 高频日志限频默认 | 同一日志点（同一调用位置/日志模板，不含变量值）每秒最多 5 条，超出丢弃；采样后的输出同样受此上限约束 |
| 逐报文日志采样默认 | 1/100 |
| 丢弃计数摘要 | 每日志点每 60 秒输出一条，含该周期丢弃条数；按被限频/采样日志的原等级输出，且不得低于 INFO |

## 规则

- LOG-01 日志必须通过所在工程统一的日志设施输出，禁止用 printf/cout 等直接打印替代日志记录，禁止自拼日志格式。
- LOG-02 管理类接口（增、删、改、查、登录/登出、导入、导出、下发）必须输出管理操作日志；失败的操作同样必须记录。
- LOG-03 管理操作日志必须包含五要素：操作用户、操作类型（枚举见参数表）、操作对象（类型 + 名称，禁止只记 ID 不记名称——名称人可读；ID 可选附注）、操作结果（成功/失败）、操作来源（源 IP 或终端标识，本地控制台记 console）；涉及字段的术语表（naming-glossary.md）标准名：operator、operation_type、operation_result、source_ip；操作对象：object_type + object_name（object_id 可选）。
- LOG-04 新增、修改、删除必须记录完整的变更内容，保证仅凭日志就能完整还原操作前后的对象状态，溯源不依赖回查系统数据：新增记录新增后的全部业务字段；修改记录变更前与变更后的全部业务字段；删除记录变更前的全部业务字段，禁止只记「删除成功」或只记名称概要。内容以字段=值逐一记录（或结构化输出）；涉敏感字段按 LOG-11 脱敏为 `******`，占位保留、字段不省略（避免溯源时无法区分「未记录」与「为空」）。失败的操作记录操作意图值与失败原因，无「变更后」要求。
- LOG-05 业务模块自身的运行事件必须输出业务日志。例：策略匹配类事件必须记录命中策略（policy_id/policy_name）、匹配内容（src_ip、dst_ip、protocol、port）、执行动作（match_action）；port 仅在 tcp/udp 等有端口语义的协议下必录，icmp 等无端口语义的协议可省略 port，改记协议相关字段（icmp 记 icmp_type/icmp_code）。
- LOG-06 高频业务日志（逐报文/循环内）必须限频或采样：逐报文日志默认采样 1/100，且采样后的输出同样受「同一日志点每秒最多 5 条」上限约束（采样与限频叠加）；其他循环内高频日志默认限频（口径见参数表）。被丢弃的日志必须按固定周期输出丢弃计数摘要，保证丢弃可观测。
- LOG-07 禁止自创日志等级；等级语义与使用场景以对照表为准。
- LOG-08 用户操作错误（用户可自行纠正：输入不合法、名称重复、参数越界等）：直接告诉用户错在哪、如何修改；记 ERROR 日志即可，无需追加 DEBUG（ERROR 中的输入值与规则已足够定位，复现方式就是用户重试；输入值涉敏感字段按 LOG-11 脱敏）；禁止降级为 INFO/DEBUG；禁止只提示"操作失败"，禁止引导用户联系管理员。
- LOG-09 系统内部错误（用户无法解决：空指针、数据库异常、消息超时等）：对用户只提示"系统内部错误，请联系我们"；禁止向用户返回堆栈、SQL、内部路径等细节；必须记 ERROR 日志，包含出错模块、对象标识、失败原因，保证不看 DEBUG 也能定位到出错的模块与对象。
- LOG-10 系统内部错误的详细出错位置（文件/行/堆栈）与难以复现问题的上下文（入参、中间状态）用 DEBUG 日志记录；入参涉敏感字段按 LOG-11 脱敏。伴随 DEBUG 与对应 ERROR 必须携带同一请求标识（请求 ID/流水号），ERROR 中包含该标识以便反查。请求标识由所在工程保证：每个管理/业务请求具有唯一标识（request_id），入口生成、跨模块调用透传；无现成机制时以本条为依据补建。
- LOG-11 全局脱敏：任何等级、任何日志均适用。凡输出参数表敏感字段清单所列字段的值（含结构化字段取值，以及拼入文案、URL、连接串中的凭据；含 LOG-03 五要素、登录失败记录、LOG-08 记录的输入值、LOG-10 记录的入参与中间状态），必须先脱敏为 `******` 再写入日志。

## 示例

✅ `admin 新增策略 "office_net"(policy_id=12, 192.168.2.0/24→10.0.0.0/8 allow tcp/443)：成功（来源 console）`
✅ `admin 删除地址对象 "server_a"(object_id=3, 10.0.0.8/32, 描述=测试服务器)：成功（来源 10.1.1.5）`
✅ `admin 删除地址对象 "server_a"(object_id=3) 失败：被策略 "guest_net"(policy_id=5) 引用（来源 10.1.1.5）`
✅ `命中策略 "block_icmp"(policy_id=7)：192.168.1.10→10.0.0.5 icmp icmp_type=8，动作=丢弃`
❌ `操作失败`（无错因、无对象标识）
❌ 向用户返回 `NullPointerException at db.c:120`（内部细节外泄）
❌ 用 `printf`/`cout` 直接打印替代日志记录，或自拼日志格式绕过统一设施
❌ 每个报文记一条匹配日志（未限频/采样）

## 完成前自检

- [ ] 日志全部走统一日志设施，无 printf/cout 直接打印或自拼格式（LOG-01）
- [ ] 每个管理类接口的成功与失败分支都有操作日志，五要素齐全，操作对象含名称（禁止只记 ID）（LOG-02/03）
- [ ] 成功的新增/修改/删除均记录了完整变更内容（全部业务字段，脱敏字段以 `******` 占位保留不省略），失败的记录了意图值与原因（LOG-04）；所有涉及敏感字段取值的输出点均已脱敏（LOG-11）
- [ ] 业务事件输出业务日志且要素齐全（LOG-05）
- [ ] 逐报文日志已采样、其他高频日志已限频，丢弃计数摘要可观测（LOG-06）
- [ ] 等级符合对照表，未自创等级（LOG-07）
- [ ] 用户操作错误：提示了错因和改法，且记 ERROR（LOG-08）
- [ ] 系统内部错误：用户侧无内部细节，ERROR 定位到模块与对象，DEBUG 含详细位置与上下文且与 ERROR 同请求标识（LOG-09/10）
