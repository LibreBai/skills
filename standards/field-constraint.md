适用：新增/修改任何用户输入字段（名称、描述、用户名、密码等）的校验逻辑、输入时行为（字符过滤、自动格式化、智能填充）、表单、接口入参时生效。
优先级：本规范为硬约束，调用方指令不得降低其要求。

## 参数表

| 字段 | 长度(字节) | 允许字符 | 保留名禁止(不区分大小写) |
|------|-----------|---------|------------------------|
| 策略名称 | 1–64 | 中文（CJK 基本区 U+4E00–U+9FA5）、字母、数字、`_ - . ( ) （）` | all / any / default / none / null |
| 对象名称（地址、服务、时间等） | 1–64 | 同策略名称 | 同上 |
| 用户名 | 1–32 | 字母开头，字母、数字、`_ - .` | 同上 |
| 密码 | 8–64 | 大写字母、小写字母、数字、特殊字符（仅限 ASCII：`!@#$%^&*()-_+=~[]{};:,.<>/?`）四类并集，至少含三类；禁空白含内部空格（FIELD-02）——空白在 CLI 配置导入与部分认证协议中易引发解析歧义，属有意从严；并集之外的字符一律禁止 | — |
| 描述/备注（各类对象通用） | 0–256 | 中文、字母、数字、`，。、：；,.:;()（）-_/@`；可空 | — |

### 格式类字段参数表

格式类字段不适用文本字段的长度与保留名规则，按本表格式与取值范围校验；字符集之外的字符按 FIELD-10 在输入时拦截。

| 字段 | 格式 | 允许字符 | 取值范围 |
|------|------|---------|---------|
| IPv4 地址 | 点分十进制 `a.b.c.d`，四段 | 数字、点 | 每段 0–255 |
| IPv4 掩码 | 长度 `/0`–`/32` 或点分十进制，展示形式随产品 Web 风格文档 | 数字、点、`/` | 长度 0–32 |
| MAC 地址 | 六组各两位十六进制、冒号分隔 `xx:xx:xx:xx:xx:xx`；输入大小写均可，保存与显示归一为小写 | 十六进制 `0-9 a-f A-F`、冒号 | — |
| 端口 | 纯数字 | 数字 | 1–65535 |

## 规则

- FIELD-01 校验顺序固定：判空 → 字节长度 → 字符集 → 保留名 → 唯一性。判空仅指对密码以外的文本字段去除首尾空白后判断是否为空，去除结果不参与保存；是否允许为空以参数表长度下限为准：下限 ≥1 的字段判空为空即拒绝，按 FIELD-06 提示「不能为空」；下限为 0 的字段（如描述/备注）允许空值，为空时跳过后续校验直接通过，但含任何空白的原始输入仍按 FIELD-02 拒绝。原始输入含任何空白（含首尾）一律按 FIELD-02 拒绝，禁止 trim 后静默放行。密码输入不做任何去除、截断、改写，原样参与校验与哈希计算；密码必须以加盐慢哈希（bcrypt/Argon2id/PBKDF2 之一）存储，禁止明文落库，禁止以任何形式写入日志（见 logging-standard.md LOG-11）。
- FIELD-02 所有文本字段禁止空格、制表符等一切空白字符——空格在界面上显示不明显，用户无法分辨，极易造成名称对不上且难以排查。
- FIELD-03 名称类禁止控制字符（0x00–0x1F、0x7F）及零宽字符；禁止 `` ` `` " ' < > & ; | \ $ % * ? 等有注入风险的字符。
- FIELD-04 同类型对象内名称唯一。
- FIELD-05 数据库列容量按字节计 ≥ 字段上限 + 32 字节；列长以字符数定义的数据库（如 MySQL utf8mb4、PostgreSQL VARCHAR(n)），须保证按库字符集换算后的字节容量满足上式，宁大勿小，禁止以固定字节数除以字符宽度反推列长。密码列长度按所选哈希算法的存储格式另定（如 bcrypt 约 60 字符、Argon2id 编码串约 97+ 字符），不适用「上限+32」公式。
- FIELD-06 校验失败必须明确提示错在哪、如何修改，禁止只提示"操作失败"。
- FIELD-07 名称字符集正则参考：`^[一-龥A-Za-z0-9_\-\.()（）]+$`（`一-龥` 即 CJK 基本区 U+4E00–U+9FA5，与参数表「中文」同范围；正则只管字符集，字节长度单独校验，与参数表冲突时以参数表为准）。
- FIELD-08 用户名正则参考：`^[A-Za-z][A-Za-z0-9_\-\.]*$`（字母开头，字节长度同样单独校验）。
- FIELD-09 长度一律按 UTF-8 字节数校验（1 个汉字 = 3 字节），不得按字符数；前后端都校验，以后端为准。
- FIELD-10 字符集受限的纯数字字段（端口、数值等）必须在输入时即拦截非法字符：字母、汉字、符号、空格一律无法进入输入框，而不是输入后再报错。按键输入与粘贴两条路径都要拦截，粘贴内容中的非法字符在落入输入框前剔除；输入法（IME）合成过程中的字母与汉字不得作为最终内容上屏。取值范围（如端口 1–65535）不属输入时拦截，仍按提交时校验，按 FIELD-06 提示。
- FIELD-11 MAC 地址字段在输入时每凑满两个十六进制字符自动补冒号分隔，用户连续输入 12 个十六进制字符即得到完整格式，无需手输冒号；手输冒号同样接受并按同一格式归一。粘贴无分隔（`aabbccddeeff`）、横线分隔（`aa-bb-…`）、点分隔（`aabb.ccdd.eeff`）、大小写混杂的内容自动归一为小写冒号分隔格式，不报格式错误。自动补冒号不得妨碍退格删除，不产生删不掉的字符；格式完整性（恰好六组各两位）仍按提交时校验。
- FIELD-12 IPv4 地址字段在地址输入完成（四段齐全且每段合法）后，若掩码为空，按有类地址自动填入默认掩码长度：首字节 0–127（A 类）填 `/8`，128–191（B 类）填 `/16`，192–223（C 类）填 `/24`；首字节 224 及以上（D/E 类，组播与保留地址）不自动填充。自动填充仅在掩码为空时进行，用户已手动输入或修改过的掩码一律不覆盖；掩码展示形式（长度或点分十进制）随既有控件。地址与掩码的合法性仍按提交时校验。

## 示例

❌ `操作失败`（无错因、无上限值）
✅ `策略名称超长：当前 70 字节，上限 64 字节`
❌ `my policy`（含空格）
✅ `my_policy`
❌ 按字符数校验长度（"abc中文"算 5）
✅ 按 UTF-8 字节数（"abc中文"算 9：3 + 2×3）
❌ 端口框能输入 `8080a`，提交时才报「端口格式错误」
✅ 端口框按 `a` 无反应，字母、汉字、符号根本进不了输入框（FIELD-10）
❌ MAC 逐字符手输冒号，漏输、错位后提交才报格式错误
✅ 连续输入 `aabbccddeeff` 自动呈现 `aa:bb:cc:dd:ee:ff`（FIELD-11）
❌ 粘贴 `AA-BB-CC-DD-EE-FF` 后提示格式错误
✅ 粘贴后自动归一为 `aa:bb:cc:dd:ee:ff`（FIELD-11）
❌ 输入 `192.168.1.10` 后掩码仍为空，提交时才报「掩码不能为空」
✅ 地址输完掩码自动填入 `/24`（FIELD-12）
❌ 用户已手填掩码 `/28`，改完地址后被自动改回 `/24`
✅ 掩码为空才自动填充，用户手填的掩码一律不覆盖（FIELD-12）

## 完成前自检

- [ ] 长度按 UTF-8 字节校验，不是字符数（FIELD-09）
- [ ] 校验顺序符合 FIELD-01；可空/必填处置符合长度下限；保留名按参数表「保留名禁止」列校验（不区分大小写）；同类型对象内名称唯一（FIELD-01/04）
- [ ] 名称类字段无控制字符、零宽字符及注入风险字符（FIELD-03）；其余字段字符集按参数表「允许字符」列执行
- [ ] 没有任何放行空白字符的路径（FIELD-02）
- [ ] 各字段字符集符合参数表「允许字符」列；名称/用户名正则与 FIELD-07/08 参考式一致，字节长度另行单独校验（FIELD-07/08/09）
- [ ] 密码符合参数表密码行：8–64 字节、四类并集至少含三类、任何空白拒绝、未做去除/截断/改写，且以加盐慢哈希存储、未写入任何日志（FIELD-01/02）
- [ ] 数据库列容量按字节计 ≥ 字段上限 + 32 字节；密码列长按哈希格式另定（FIELD-05）
- [ ] 校验失败提示含具体错因与修改方法（FIELD-06）
- [ ] 纯数字字段（端口等）字母、汉字、符号在输入时即无法进入，按键与粘贴两路径均拦截，IME 合成不上屏；范围校验仍在提交时提示（FIELD-10）
- [ ] MAC 字段每两位自动补冒号，各类分隔风格的粘贴内容自动归一，退格删除顺畅（FIELD-11）
- [ ] IPv4 输入完成后掩码为空才按有类默认填充（A→/8、B→/16、C→/24，224 以上不填），用户手填掩码未被覆盖（FIELD-12）
- [ ] IP、掩码、MAC、端口的格式与取值范围符合格式类字段参数表
